# Этап 1: настройка окружения

## Текущее состояние

Проект Supabase **Cash Radar**, ref `mawljmoijqhcdbmszglq`, создан владельцем в регионе `ap-northeast-1` (Токио); регион подтверждён владельцем. URL API: `https://mawljmoijqhcdbmszglq.supabase.co`. Миграция применена 11.11.2026; интеграционный тест Flutter с публичным ключом вызвал функцию через Data API и получил `ok` от PostgreSQL.

Миграция `supabase/migrations/20261111000000_health_check.sql` создаёт не меняющую данные функцию `public.cash_radar_health()`. Она возвращает `ok` и не раскрывает пользовательские данные. В облачной базе проверено: права `EXECUTE` есть у `anon` и `authenticated`, нет у `PUBLIC`; функция работает с правами вызывающего.

## Требования

- Flutter 3.44.9 stable и Dart 3.12.2; приложение использует `supabase_flutter`, точные версии зависимостей закреплены в `app/pubspec.lock`.
- Node.js и Supabase CLI 3 для работы с миграциями. CLI можно запускать через `npx --yes supabase@3` из корня репозитория; при работе в команде стоит зафиксировать версию.
- Docker-совместимая среда для стандартного локального стека Supabase. Пока Docker/Podman в PATH не обнаружены, локальная БД не настроена. В `supabase/config.toml` указана PostgreSQL 17; версия удалённой базы проверена: 17.11.
- Android SDK с принятыми лицензиями для Android; Xcode для iOS; Chrome для Flutter Web. При проверке `flutter doctor` отмечены непринятые лицензии Android.

## Работа с миграциями

Миграция этапа 1 уже применена к проекту Cash Radar. Перед применением новых миграций проверяйте удалённую историю и предварительный список изменений; не сбрасывайте и не перезаписывайте БД. При наличии расхождений сначала согласуйте историю миграций.

```sh
# Из корня репозитория; авторизация выполняется локально, токен в чат не отправляется.
npx --yes supabase@3 login
npx --yes supabase@3 link --project-ref mawljmoijqhcdbmszglq
npx --yes supabase@3 migration list --remote
npx --yes supabase@3 db push --dry-run --remote
npx --yes supabase@3 db push --remote
```

CLI может запросить пароль базы в терминале. Перед подтверждением убедитесь, что целевой проект — Cash Radar и показана только ожидаемая миграция. Не запускать `db reset --remote`. Публичный API-ключ не позволяет применять миграции. Дальнейшая проверка в приложении подтвердит фактическую доступность функции через Data API.

## Конфигурация и запуск приложения

SQL-проверка `supabase/tests/health_check.sql` выполняется на изолированной тестовой БД после миграции. На этапе подготовки миграция и права ролей успешно проверены в изолированном PGlite (PostgreSQL WASM); полноценный Supabase и облачная БД этим не проверяются.

1. В Supabase Dashboard откройте проект Cash Radar → Connect или Settings → API Keys. Найдите **publishable key** (допустим и прежний `anon` key). Не используйте `service_role`, `secret key`, токен доступа или пароль базы: они не предназначены для приложения.
2. Из корня репозитория создайте локальный файл:

   ```sh
   test -f app/config/local.json || cp app/config/example.json app/config/local.json
   ```

3. В `app/config/local.json` задайте URL `https://mawljmoijqhcdbmszglq.supabase.co` и публичный ключ. Файл исключён из Git. Публичный ключ всё равно попадёт в клиентскую сборку и не считается секретом; права ограничиваются RLS и серверной проверкой.
4. После применения миграции запустите:

   ```sh
   cd app
   flutter pub get
   flutter run -d chrome --dart-define-from-file=config/local.json
   ```

5. Нажмите «Проверить подключение». Успешная проверка возвращает `ok` из PostgreSQL через API; ошибки конфигурации, отсутствующая миграция и недоступная сеть выводятся без секретных данных.

Приложение сейчас принимает только HTTPS URL. Для локальной Supabase-среды потребуется отдельно предусмотреть безопасный development-режим с HTTP на loopback, прежде чем указывать локальный адрес; не отключайте проверку сертификатов.

Секреты для будущих серверных интеграций следует передавать через безопасные переменные окружения/секреты Supabase, а не во Flutter и не в Git. Пример `app/config/example.json` содержит только заполнители.

## Проверки

```sh
cd app
flutter analyze
flutter test
flutter build web
# Реальное подключение: локальный config/local.json должен быть заполнен.
flutter test --dart-define-from-file=config/local.json \
  --dart-define=RUN_SUPABASE_INTEGRATION_TESTS=true \
  test/connection_integration_test.dart
```

В обычном запуске интеграционный тест пропущен, чтобы проверки не зависели от сети и конфигурации. Тесты интерфейса используют подставной результат подключения и не заменяют проверку реального проекта. Android/iOS-сборки и изоляция пользователей требуют отдельных проверок.

## Окружения и данные

Пока создан только один облачный проект; не считать его одновременно безопасным development и production. Тестируйте на искусственных данных, не загружайте банковские выписки до настройки RLS, политики Storage и проверенного восстановления. Второй облачный проект или локальную инфраструктуру определить после проверки доступной квоты; платные ресурсы без согласия не подключать.
