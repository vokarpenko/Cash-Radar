# Категоризация

В «Настройки → Правила категорий» можно добавить правило по части названия, точному названию или четырёхзначному MCC. Правило задаёт тип операции, категорию и приоритет от 0 до 10000; более высокий приоритет проверяется раньше. При одинаковом приоритете выигрывает более конкретное название, затем более раннее правило. Правило можно отключить или удалить. Явно заданные пользователем правила имеют приоритет перед остальными способами.

Алиас связывает исходное название с общим; для него можно сразу выбрать категорию или оставить её пустой и использовать правило для общего названия. Затем проверяется правило MCC и, если ничего не подошло, запомненное исправление. Если соответствия нет, используется категория по умолчанию. Никаких предустановленных предположений о торговых точках нет; категории и правила владелец выбирает сам.

При изменении категории существующей операции запоминается нормализованное название этой операции и новый выбор. Такие соответствия видны в настройках и могут быть удалены. Приоритет пользовательских правил выше запомненных исправлений. Для ACBA берётся отдельное поле места операции, для Ameria — исходное описание, так как надёжно выделить из него merchant пока нельзя. Исходные данные не изменяются. MCC применяется только при наличии корректного кода в данных парсера; имеющиеся проверенные выписки не дают подтверждённого поля MCC, разбор Альфа-Банка отложен.

Правила применяются к новым строкам банковских выписок до предпросмотра. В уже подготовленной банковской выписке их можно применить повторно кнопкой «Применить правила категорий». Явные категории CashRadar CSV и ручной ввод сохраняются без автоматической замены. Изменение правил не переписывает прошлые операции. В предпросмотре виден источник категории; комиссия остаётся отдельным расходом. Названия и правила доступны только владельцу через политики RLS.

## Gemini и запоминание соответствий

AI запускается только по явному действию пользователя в выбранном импорте. В раскрывающемся списке необходимо отметить до десяти публичных названий, которые пользователь согласен передать Google. Автоматический фильтр блокирует некоторые номера, адреса и другие подозрительные строки, но не может подтвердить, что название публичное. Для Ameria может отображаться целое описание строки: его следует выбирать только после проверки. Бесплатный тариф Google допускает использование запросов для улучшения продуктов; название продавца может раскрыть сведения о покупке. Суммы, даты, номера счетов, файлы, идентификаторы пользователя и операций в запрос не включаются. Передаются выбранное название, тип операции и временный номер строки. [Условия Gemini API](https://ai.google.dev/gemini-api/terms).

Сначала применяются обычные правила, алиасы, MCC и ручные исправления. Одинаковые неизвестные названия одного типа группируются; уже сохранённое или отключённое AI-соответствие и предложения на проверке повторно не отправляются. Модель `gemini-4-hydrogen` вызывается только серверной функцией. Ключ находится в секретах сервера, ответ проверяется на структуру, идентификаторы, допустимые категории и тип операции. При ошибке или истечении лимита данные не меняются.

Ответу с оценкой уверенности не ниже 0,9 и признаком однозначности создаётся точное соответствие для владельца и типа операции; от 0,6 — предложение в настройках. Это эвристика модели, а не статистически проверенная вероятность, поэтому результаты следует проверять. Неизвестные и неподдерживаемые категории оставляются без изменений. AI выбирает из фиксированного списка и сопоставляется с пользовательскими категориями по названию; если подходящая категория переименована или отсутствует, соответствие не создаётся. В настройках AI-соответствие можно исправить, отключить или удалить; ручные правила и исправления имеют приоритет. При конфликтующем ручном исправлении соответствие отключается. При принятии предложения нажмите «Применить правила категорий» в подготовленной выписке. Ранее подтверждённые операции автоматически не меняются; правила по ним влияют на будущие импорты.
