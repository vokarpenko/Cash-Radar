# Формат CashRadar CSV

Это простой формат для проверки общего механизма импорта. Он не является форматом банковской выписки. Выписки Ameria и ACBA XLSX поддерживаются отдельными парсерами; другие банковские форматы предусмотрены на следующих этапах.

Файл должен быть в UTF-8, не более 1 МиБ и 500 строк операций. Первая строка — точный заголовок в указанном порядке. Пример для счёта в AMD:

```csv
date,type,amount,currency,account_amount,category,description
2026-11-11,expense,1250.50,AMD,,Продукты,Покупка
2026-11-12,expense,12.34,EUR,6000.00,Рестораны,"Кофе, обед"
2026-11-12,income,100000.00,AMD,,Зарплата,Зарплата
```

- `date` — календарная дата `ГГГГ-ММ-ДД`, от 1900-01-01 до 2100-12-31.
- `type` — `income` или `expense`; сумма задаётся положительным числом, знак определяется типом.
- `amount`, `currency` — фактическая сумма и валюта операции. Валюты: AMD, RUB, USD, EUR. Максимум два знака после десятичного разделителя, без округления. При десятичной запятой поле нужно заключить в кавычки: `"12,34"`.
- `account_amount` — фактическая сумма в валюте выбранного счёта. Для совпадающих валют поле можно оставить пустым, иначе его нужно заполнить; конвертация по курсу не выполняется.
- `category` — название существующей категории пользователя соответствующего типа; регистр и пробелы по краям не учитываются. При одинаковых названиях категорий одного типа импорт сообщит об неоднозначности.
- `description` — необязательное описание до 500 символов; если поле содержит запятую или кавычки, используйте стандартные CSV-кавычки и удваивайте внутренние кавычки.

После выбора счёта и файла сервер определяет формат по содержимому, проверяет данные и сохраняет оригинал в приватном Storage. Предпросмотр содержит корректные строки и ошибки; если есть ошибки, частичное подтверждение запрещено. Исправьте файл и загрузите снова. Раздел «Импорт» позволяет отменить подготовку: исходный файл остаётся в закрытом хранилище.

Повторный файл определяется по SHA-256 его содержимого для одного пользователя, независимо от имени файла и выбранного счёта. Уже подготовленный или импортированный файл повторно не создаёт операции. Файл с ошибками или отменённую подготовку можно обработать снова. Подтверждение выполняется атомарно и повторное нажатие не создаёт копии.

XLSX Ameria и ACBA принимаются отдельными парсерами. Неподдерживаемые XLSX/ZIP и PDF отклоняются с понятным сообщением до загрузки в хранилище. Правила удаления сохранённых оригиналов и полноценное управление сроками хранения предстоит реализовать отдельно.
