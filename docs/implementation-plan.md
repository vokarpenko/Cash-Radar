# CashRadar: план реализации

Статус на 11.11.2026: этапы 0–3 выполнены; модель данных и RLS проверены локально, миграции применены к облаку. Следующий этап — базовый интерфейс и публикация Web после разрешения владельца. Порядок и объём определяет [мастер-ТЗ](cash_radar_brd.md). Каждый этап выполняется отдельно, с подходящими проверками и обновлением документации; переход — только после сообщения владельца.

## Результаты аудита этапа 0

Исторический снимок до создания репозитория и облачного проекта; актуальное состояние этапа 1 — в [инструкции по настройке](setup.md).

- В рабочем каталоге был только `cash_radar_brd.md`; исходного кода, `pubspec.yaml`, миграций и зависимостей проекта не обнаружено. Банки и функциональность ещё не реализованы.
- Каталог не является Git-репозиторием. Git 2.54.0 доступен; глобальные `user.name` и `user.email` заданы, начальная ветка глобально не задана. Репозиторий и удалённый адрес не создавались: пользователь планирует загрузку позднее.
- FVM указывает на Flutter 3.44.9 stable; версия прочитана из `bin/cache/flutter.version.json`. `flutter --version` не выполнился: песочница запрещает запись в кэш SDK вне рабочего каталога. Поэтому работоспособность Flutter и готовность платформенных инструментов не подтверждены. Dart 3.12.2 stable (`macos_arm64`) подтверждён прямым запуском бинарного файла SDK.
- `supabase`, `docker`, `podman` и `psql` не найдены в PATH; Node и npm доступны. Наличие другого контейнерного runtime и состояние Supabase-аккаунта не проверены. Нужны Supabase CLI и работающая Docker-совместимая среда для стандартного локального стека; альтернативный native runtime Supabase экспериментален и имеет ограничения платформы.
- Зависимости и версии библиотек приложения пока не зафиксированы. Доступы к облаку, регион, свободные проекты и квоты необходимо уточнить без передачи секретов в чат.

## Подготовка этапа 1: исторический план

1. Уточнить, есть ли аккаунт и подходящий проект Supabase, доступная Free-квота и приемлемый регион хранения. Не просить присылать токены или пароли в чат.
2. Выяснить, как запускать Flutter с доступом к его кэшу; проверить `flutter doctor` и необходимые платформенные инструменты. Выбрать установку Supabase CLI и доступный локальный runtime, проверив версии и требования на момент установки.
3. Решить, есть ли смысл в отдельном облачном dev-проекте и хватит ли квоты. Для разработки использовать искусственные данные; до проверки изоляции и восстановления не загружать реальные выписки.
4. Создать только минимальную структуру Flutter и Supabase, необходимую для работающей проверки этапа; не внедрять auth UI, модель финансовых данных, миграции будущих этапов и банковские интеграции.
5. Проверить миграцию на чистой базе, доступность backend и базы, конфигурацию без секретов в клиенте; описать необходимые шаги и ограничения. Облачную проверку нельзя считать выполненной без фактического подключения.
